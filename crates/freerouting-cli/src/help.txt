USAGE
  freerouting-rs -de <design.dsn> -do <output.ses> [PARAMETERS]
  freerouting-rs -de <design.dsn> -drc [report.json] [PARAMETERS]

Settings are read from, in order of priority (the last wins): the built-in
defaults, the routing profile, the settings file, the DSN file,
FREEROUTING__ROUTER__* environment variables, then the command line. Router
flags set the settings named under them; the names are the JSON paths of the
settings table.

ROUTING PROFILES
  --profile enhanced (the default) routes with the accepted improvements
  over Java Freerouting; --profile legacy gives results identical to Java
  Freerouting. A profile only sets defaults: every stage and option can
  still be set on its own, and an explicit setting always wins.
  --list-stages shows the stages and options each profile starts with.

EXPERIMENTAL OPTIONS
  Off in every profile, each with the board class it wins on and its
  measured numbers in --list-stages (the "Experimental" section):
  --router.room_order=canonical, --router.work_unit=leaves, and the stage
  --router.special.diff_pairs=krt-diffpair. They are kept under N02's rule:
  they win on a nameable board class or wait for a measurement, and none is
  a default.

PARAMETERS
  -de <design.dsn>[+<session.ses>][+<design.rules>]
      Load the Specctra design file. The files may also be separate
      arguments, in any order; the last .dsn wins. A KiCad board
      (<design>.kicad_pcb) is read directly, with the <design>.kicad_pro and
      <design>.kicad_dru next to it; the read report is printed.
  -di <design_directory>
      Accepted and ignored (the folder of the GUI's open dialogs).
  -dr <design_rules_file>
      Read routing rules from a .rules file. Without it an adjacent
      <design>.rules is read if it exists.
  -do <output.ses>[+<other output>]
      Save the result. The first file is the main output; others are extra
      outputs. Written formats: .ses, .dsn, .rules, .drc and .drc.json (the
      design rules check report), and .kicad_pcb for a .kicad_pcb input: a
      copy of the input with the routed tracks and vias (never the input
      itself). Anything else (.frb, .scr, .json) is refused before any work.
      A file is written whole or not at all, and never with 0 bytes.
  -drc [report.json]
      Check the design rules of the design (and session) and write the
      report, to standard output without a file. Nothing is routed.
  -mp <number_of_passes>
      Maximum number of auto-routing passes; 0 or more than 9999 means
      unlimited.
      Setting: autorouter.max_passes [default: 0]
  -mt <number_of_threads>
      Accepted, and as in Java it has no effect on a headless run (it sets
      the flat max_threads, which no stage reads). Use
      --router.optimizer.max_threads for the optimizer.
      Setting: max_threads
  -oit <threshold>
      Optimizer improvement threshold; a value between 0 and 1 is a fraction
      (deprecated; use --router.optimizer.improvement_threshold).
      Setting: optimizer.improvement_threshold [default: 2.5]
  -inc <class>[,<class>...]
      Net classes the autorouter leaves alone (deprecated; use
      --router.autorouter.ignore_net_classes). Names are split on commas; a
      backslash keeps a comma: -inc 'Power\,Default' is one class named
      Power,Default.
      Setting: autorouter.ignore_net_classes
  -us <strategy>, -is <strategy>
      Accepted and ignored.
  -l <language>, -dl, -da, -dct <seconds>, -host <name>
      Accepted and ignored (GUI language, file logging, analytics, dialog
      timeout and the name of the calling program).
  -ll <level>
      Console log level: TRACE, DEBUG, INFO (the default), WARN, ERROR or OFF.
  -h, -help, --help
      Display this help.

LONG FLAGS
  --router.<path>=<value>, --optimizer.<path>=<value>
      Set any router setting by its path, for example
      --router.autorouter.max_passes=5 or --router.scoring.via_costs=40.
  --scoring-version=<v1|v2>, --router-scoring-version=<v1|v2>,
  --optimizer-scoring-version=<v1|v2|lower_bound>
      Choose the score versions.
      Setting: router_scoring.version, optimizer_scoring.version
  --settings <file>
      Read this settings file (JSON, as Java's freerouting.json) instead of
      the default <config dir>/freerouting-rs/freerouting.json.
  --user_data_path=<dir>
      Read <dir>/freerouting.json.
  --logging.console.level=<level>
      The same as -ll.
  --gui.*, --api_server.*, --mcp_server.*, --usage_and_diagnostic_data.*,
  --feature_flags.*, --profile.*, --debug.*, --logging.*
      Accepted and ignored (--profile.<key>=<value> is Java's user profile;
      --profile <name> is the routing profile).

NOT SUPPORTED
  --compare-boards=<a>,<b> and --calculate-benchmark-scores exit 2; use
  freerouting-dev ses-diff.

PLUGIN FLAGS (not in Java)
  --version
      Print one line, `freerouting-rs <version> (git <sha>)`, and exit.
  --capabilities
      Print what this build can do as JSON (version, output formats, every
      flag, exit codes, schema versions, stage ids) and exit.
  --progress json
      Every stderr line is one JSON object: `start`, `progress` (phase load,
      fanout, route, optimize or write, with pass, routed, failed, ripped,
      incomplete, violations, score and elapsed_ms), `log` and `done`. The
      events are counted, never timed.
  --result-json <file>
      Write a machine-readable result manifest (Java's RoutingResultManifest,
      schema version 1) when the run ends, also when it failed. With
      --router.output_check=report or repair (profile enhanced's value) it
      has one more key, output_check: mode, checked (routed traces and vias
      checked), found (their breaches of the board's rules), removed,
      retried (connections tried again), repaired, left_open, remaining,
      by_rule (breaches per rule: clearance, copper_edge_clearance, keepout,
      track_width, via_diameter, drill_out_of_range, annular_width,
      hole_clearance, solder_mask_bridge, via_in_pad, track_dangling,
      via_dangling), input (the input's own breaches per rule, never
      changed).
      Setting: result_json
  --timeout <duration>
      Stop the job after this long and keep the best board: 90s, 10m, 2h,
      HH:MM:SS or plain seconds; at most 24 hours. The same as job_timeout.
      Setting: job_timeout
  --max-passes <number>
      The same as -mp.
      Setting: autorouter.max_passes
  --threads <number>
      Threads of the autorouter and the optimizer; never changes the result.
      Setting: autorouter.max_threads, optimizer.max_threads
  --apply-design-rules
      With a .kicad_pcb input, apply the rules of the <design>.kicad_dru that
      the router can express to the board, as --kicad-dru does for a DSN.
      This is the default for a route; the switch only says so. Other inputs
      ignore it with a warning.
  --no-design-rules
      With a .kicad_pcb input, read and report the <design>.kicad_dru but
      apply none of its rules. Other inputs ignore it with a warning.
  --kicad-dru <design.kicad_dru>
      With a DSN input, apply the board's KiCad custom rules that the router
      can express: class-pair clearances, class track widths, clearances
      between item types (tracks, vias, plated and SMD pads), hole
      clearances (plated holes to tracks as via and pad clearances, others
      raising router.hole_clearance_um) and hole-to-hole distances, which
      raise router.board_minimums.hole_to_hole_um. A rule the router can
      only apply more widely is applied with a warning; one that asks for no
      more than the DSN gives is reported and left out. A .kicad_pcb input
      ignores it with a warning: it applies the .kicad_dru next to it.
  --router.input_fixups.class_widths=<class>=<um>[,...]
  --router.input_fixups.route_on_plane_layers=<layer>[,...]
  --router.input_fixups.drop_pour_nets=<net>[,...]
  --router.input_fixups.fixed_pour_classes=<class>[,...]
      With a .kicad_pcb input, change the board as the KiCad plugin's DSN
      fix-ups change KiCad's export (K14): set each class's track width, in
      micrometers; make each plane (power) layer a signal layer, keeping its
      planes; leave each net's zones on the outer copper layers out of the
      planes, keeping its inner-layer zones; cover each filled zone on the
      outer copper layers whose net is in a listed class with fixed wires of
      its net, from the zone's fill in the file, in place of its plane (a
      dropped net is dropped instead). The fixed wires are never written to
      the session or to a .kicad_pcb output. A class or layer the board does
      not have, or a layer that is not a plane layer, fails the run with a
      message naming it; an unknown net is a warning. A class whose width an
      applied .kicad_dru track_width rule sets keeps the rule's width. Off by
      default under both profiles. A DSN input ignores them with a warning.
  --seed <number>
      Reserved. 0 means Java's own seeds; any other value is refused.
  --profile <legacy|enhanced>
      The routing profile: legacy for results identical to Java Freerouting,
      enhanced (the default) for the accepted improvements. The same as
      --router.profile=<name>; any other name is a usage error.
      Setting: profile
  --list-stages[=json]
      Print every routing stage slot (fanout, net ordering, connection
      router, rip-up policy, pass controller, plane taps, neck-down, the
      special stages, optimizer, diagnostics), the stage ids registered for
      it, the id the profile starts with and the slot's options with the
      profile's defaults, as a table or as JSON, and exit.
  --dump-settings[=json]
      Print every setting with its effective value and the source that set
      it, marking the values set by the profile and those that differ from
      the profile's, and exit. With -de the design is loaded as for a run.

DEVELOPER FLAGS (not in Java; not in --capabilities)
  --stats json
      Write the work counts and wall time of each stage (load, fanout, every
      autorouter pass, every optimizer pass, drc, write) to
      <output>.stats.json. The route is the same with and without it.
  --stats-out <file>
      Write the statistics to this file instead.

STOPPING A RUN
  Lines on standard input, whole lines, any case:
    stop         finish the current step, write the best board, exit 0
    stop-router  stop the router and let the optimizer run
  End of input is not a stop. A stop during the load, or a second interrupt,
  aborts the run: nothing is written and the exit code is 130.

EXIT CODES
  0    the job finished (or timed out) and wrote an output file; incomplete
       connections are in the log and the result manifest
  1    failure with no output: a load error, an engine error, a write failure
  2    usage error found before any work: missing -de or -do, an unsupported
       file format, a missing or malformed --settings file, a bad value for
       --progress, --timeout, --max-passes, --threads, --seed or --profile, a
       Java command that is not supported
  130  aborted before an output was written
